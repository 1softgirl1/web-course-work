# Документация По Базе Данных

## Назначение

Backend хранит учетные записи пользователей, профили врачей, карточки пациентов, обследования и значения показателей обследований.

Пациент больше не имеет ФИО в backend: единственный отображаемый идентификатор пациента — `patientCode`, который хранится в `users.username`.

## Основные Таблицы

### `users`

Хранит учетные записи для входа.

- `username` — единый идентификатор пользователя.
- `password_hash` — хэш пароля.
- `role` — `PATIENT`, `DOCTOR` или `DOCTOR_EXTENDED`.
- `status` — статус учетной записи.

Для врача в `username` хранится email. Для пациента в `username` хранится код пациента.

### `doctor_profiles`

Хранит профиль врача:

- ссылка на `users`;
- ФИО врача;
- специализация;
- место работы;
- регион.

### `patient_profiles`

Хранит медицинскую карточку пациента:

- `user_id` — ссылка на учетную запись пациента;
- `region_id` — регион пациента;
- `birth_date` — дата рождения;
- `diagnosis` — диагноз;
- `valve_name`, `valve_size`, `valve_material` — параметры клапана;
- `operation_anesthesia`, `operation_duration_minutes`, `operation_delivery_system` — параметры операции;
- `medications` — текущие медикаменты;
- `created_at` — дата и время создания карточки.

В таблице нет `patient_code`, `last_name`, `first_name`, `middle_name` и `age`. Код пациента берется из `users.username`, возраст при необходимости считается на frontend по `birth_date`.

### `examinations`

Хранит append-only журнал обследований пациента:

- `patient_id`;
- `title`;
- `exam_date`;
- `comment`.

### `characteristics`

Хранит фиксированный справочник характеристик обследований. Сейчас это 50 placeholder-характеристик.

- `code` — стабильный код характеристики для API.
- `name` — отображаемое имя.
- `unit` — единица измерения.

### `examination_characteristics`

Хранит значения характеристик в рамках конкретного обследования.

- `examination_id`;
- `characteristic_id`;
- `value`;
- `comment`.

Единица измерения не дублируется здесь, она берется из `characteristics.unit`.

### `refresh_tokens`

Хранит refresh-сессии.

- В БД хранится hash refresh token, а не сырой token.
- Сессии multi-session: у пользователя может быть несколько активных устройств.
- Refresh-ротация отзывает старую refresh-сессию и создает новую.

## Важные Решения

- Данные для входа отделены от профильных данных.
- ФИО пациентов не хранится и не возвращается API.
- ФИО врачей хранится в `doctor_profiles`.
- `patientCode` не дублируется в `patient_profiles`.
- Врач видит пациентов по правилам `scope=own` и `scope=all`, но оба режима возвращают пациентов без ФИО.
- Прямая связь пациент-врач отсутствует: доступ строится через регион пациента и регион врача.
