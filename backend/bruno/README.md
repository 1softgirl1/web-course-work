# Набор тестов Bruno

Это готовая коллекция Bruno для backend API.

## Перед запуском

1. Запусти backend на `http://localhost:8080`.
2. При необходимости заполни базу демо-данными:

```powershell
Get-Content .\backend\doc\demo-seed.sql | docker exec -i web-course-work-postgres psql -U postgres -d web_course_work
```

3. Открой папку `backend/bruno` в Bruno.
4. Выбери окружение `local`.

## Запуск Из Терминала

Если Bruno CLI не установлен глобально как `bru`, коллекцию можно запустить через `npx`:

```powershell
cd .\backend\bruno
npx --yes @usebruno/cli run . -r --env local
```

Перед запуском CLI backend должен быть доступен на `http://localhost:8080`, а база должна быть заполнена `demo-seed.sql`.

## Что делает коллекция

- проверяет вход врача, расширенного врача и пациента;
- проверяет refresh/logout и смену собственного пароля;
- проверяет список пациентов своего региона и всех регионов;
- проверяет создание пациента, карточку пациента и доступы по ролям;
- проверяет создание, чтение и редактирование обследований;
- проверяет редактирование карточки пациента;
- проверяет управление врачами для `DOCTOR_EXTENDED`.

## Порядок запуска

Лучше запускать сверху вниз:

1. `01-auth`
2. `02-bootstrap`
3. `03-doctor-patients`
4. `04-create-patient`
5. `05-patient-card`
6. `06-examinations`
7. `07-patch-patient`
8. `08-doctors`
9. `09-password-change`

## Что лежит в папках

### `01-auth`
Тесты авторизации и сессий.

- вход врача;
- вход врача с расширенными правами;
- вход пациента;
- неверный пароль;
- невалидное тело запроса;
- вход внешнего врача;
- обновление токенов;
- отклонение старого refresh-токена;
- вход врача перед logout;
- logout;
- повторный logout;
- отклонение отозванного refresh-токена;
- отклонение неизвестного refresh-токена;
- проверка запроса с устаревшим bearer-заголовком.

### `02-bootstrap`
Поднимает из базы id демо-пациентов и кладет их в runtime-переменные.

- `seedOwnPatientId`
- `seedSecondOwnPatientId`
- `seedRedPatientId`
- `seedForeignPatientId`
- `seedFarPatientId`

### `03-doctor-patients`
Тесты списка пациентов врача.

- `scope=own`;
- `scope=all`;
- фильтр по региону;
- фильтр по диагнозу;
- пагинация;
- доступ без токена;
- доступ пациентом;
- невалидный `scope`;
- невалидная пагинация.

### `04-create-patient`
Создание карточки пациента врачом.

- успешное создание;
- проверка, что новый пациент появляется в `scope=own`;
- невалидное тело;
- запрет для пациента.

### `05-patient-card`
Проверка доступа к карточке пациента.

- врач своего региона видит полную карточку;
- врач чужого региона видит обезличенную карточку;
- пациент видит свою карточку;
- чужой пациент получает `403`;
- несуществующий пациент получает `404`.

### `06-examinations`
Тесты журнала обследований.

- добавление обследования врачом своего региона;
- добавление обследования врачом с расширенными правами;
- просмотр истории обследований пациентом;
- просмотр истории обследований врачом;
- запрет для обычного врача на чужой регион;
- запрет для пациента на добавление обследования;
- пустой список измерений;
- дубли `characteristicCode`;
- неизвестная характеристика;
- редактирование обследования;
- добавление нового показателя к обследованию;
- редактирование обследования врачом с расширенными правами;
- запрет для обычного врача на чужой регион;
- запрет для пациента;
- невалидный payload;
- несуществующее обследование или характеристика.

### `07-patch-patient`
Частичное редактирование карточки пациента.

- создание отдельного пациента для patch-flow;
- вход созданным пациентом перед сменой пароля;
- редактирование пациента своего региона;
- редактирование пациента чужого региона врачом с расширенными правами;
- проверка, что логин не меняется;
- отклонение старого patient-token после смены пароля;
- пустое тело;
- невалидные значения;
- запрет обычному врачу на чужой регион;
- несуществующий пациент.

### `08-doctors`
Управление врачами для `DOCTOR_EXTENDED`.

- создание врача;
- создание врача с расширенными правами;
- получение профиля текущего врача обычным врачом;
- получение профиля текущего врача врачом с расширенными правами;
- список врачей;
- фильтры по роли, региону и статусу;
- редактирование врача;
- сброс пароля врача;
- вход после сброса пароля;
- запрет обычному врачу;
- запрет пациенту;
- дубликат username;
- невалидное тело;
- несуществующий врач;
- запрет менять собственную роль;
- реактивация врача после изменения статуса.

### `09-password-change`
Самостоятельная смена пароля.

- создание одноразового врача, пациента и врача с расширенными правами для password-flow;
- смена пароля одноразового врача;
- проверка входа новым паролем;
- отклонение старого пароля;
- отклонение старого refresh-токена;
- отклонение чужого refresh-токена;
- смена пароля одноразового пациента;
- вход пациента новым паролем;
- смена пароля одноразового врача с расширенными правами;
- неверный текущий пароль;
- запрос без bearer;
- слишком короткий новый пароль;
- refresh-токен другого пользователя.

## Важные замечания

- `09-password-change` больше не меняет пароли seed-пользователей. Он создает отдельных одноразовых пользователей и меняет пароли только им.
