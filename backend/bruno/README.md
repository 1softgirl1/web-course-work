# Набор Тестов Bruno

Это готовая коллекция Bruno для проверки backend API.

## Перед Запуском

1. Запусти backend на `http://localhost:8080`.
2. Для локальных demo-данных запускай backend с Spring-профилем `local` из папки `backend`:

```powershell
.\gradlew.bat bootRun --args='--spring.profiles.active=local'
```

3. Открой папку `backend/bruno` в Bruno.
4. Выбери окружение `local`.

## Запуск Из Терминала

```powershell
cd .\backend\bruno
npx --yes @usebruno/cli run . -r --env local
```

Перед запуском CLI backend должен быть доступен на `http://localhost:8080`, а база должна быть создана с профилем `local`, чтобы применились demo-миграции из `db/local-migration`.

## Что Проверяет Коллекция

- Авторизацию, refresh/logout и смену собственного пароля.
- Список пациентов врача в режимах `scope=own` и `scope=all`.
- Создание карточки пациента без ФИО пациента.
- Получение карточки пациента и правила доступа.
- Создание, чтение и редактирование обследований.
- Редактирование карточки пациента.
- Управление врачами для `DOCTOR_EXTENDED`.

## Папки

### `01-auth`

Проверяет вход врача, врача с расширенными правами и пациента, refresh-ротацию, logout, повторный logout и негативные сценарии с неверными credentials/token.

### `02-bootstrap`

Поднимает из demo-БД id и коды пациентов и сохраняет их в runtime-переменные Bruno:

- `seedOwnPatientId`
- `seedSecondOwnPatientId`
- `seedRedPatientId`
- `seedForeignPatientId`
- `seedFarPatientId`

Local demo migrations также содержат дополнительные регионы для ручной проверки фильтров и UI-списков:

- Кемеровская область (`regionId=22`);
- Москва (`regionId=33`);
- Новосибирская область (`regionId=39`);
- Пермский край (`regionId=44`);
- Санкт-Петербург (`regionId=67`);
- Томская область (`regionId=76`);
- Красноярский край (`regionId=26`).

### `03-doctor-patients`

Проверяет список пациентов:

- `scope=own` возвращает только регион врача.
- `scope=all` возвращает пациентов всех регионов.
- Оба режима возвращают пациентов без `lastName`, `firstName`, `middleName`.
- Проверяются фильтры `regionId`, `diagnosis`, пагинация и ошибки доступа.
- Базовые Bruno-проверки продолжают использовать core-пациентов из регионов `1`, `2`, `3`, а расширенный seed нужен для ручного frontend/backend тестирования разнообразных регионов.

### `04-create-patient`

Проверяет создание пациента врачом, появление нового пациента в `scope=own`, невалидный body и запрет создания пациентским токеном.

### `05-patient-card`

Проверяет карточку пациента:

- врач своего региона получает `FULL`;
- врач чужого региона получает `ANONYMIZED`;
- пациент получает только свою карточку;
- чужой пациент получает `403`;
- несуществующий пациент дает `404`.

ФИО пациента не проверяется, потому что оно больше не хранится и не возвращается API.

### `06-examinations`

Проверяет журнал обследований: добавление, чтение, редактирование, upsert показателей, запреты по ролям/регионам и ошибки на плохие характеристики/payload.

### `07-patch-patient`

Проверяет частичное редактирование карточки пациента: медицинские поля, регион, пароль пациента, запрет для чужого региона и ошибки на пустой/невалидный patch.

### `08-doctors`

Проверяет управление врачами для `DOCTOR_EXTENDED`: создание, список, профиль текущего врача, редактирование, reset пароля, запреты для обычного врача/пациента и негативные сценарии.

### `09-password-change`

Проверяет самостоятельную смену пароля для одноразовых пользователей, чтобы не ломать demo-логины из seed. После смены старый пароль и старые refresh tokens отклоняются.

## Важно

- `V1000__reset_demo_runtime_users.sql` удаляет runtime-пользователей Bruno по префиксам `bruno.%` и `PT-%`, поэтому полный прогон лучше начинать на свежей локальной БД или после пересоздания volume.
- `09-password-change` не меняет пароли seed-пользователей, а создает одноразовых пользователей.
- `backend/bruno/results.json` не нужен для коммита, это локальный результат запуска.
