# Прогресс курсовой работы 

## Backend

**Оценка готовности backend: 70%**

Что уже сделано:
- Стек соответствует: `Kotlin + Spring Boot`.
- Архитектура слоями присутствует: `api/controller -> service -> repository`, есть DTO.
- Валидация входа есть (`@Valid`, `@Validated`).
- Единый формат ошибок реализован через `@RestControllerAdvice` (`ApiExceptionHandler`).
- Безопасность реализована: `Spring Security + JWT + роли` (`PATIENT`, `DOCTOR`, `DOCTOR_EXTENDED`) с ограничениями endpoint'ов.
- БД: `PostgreSQL + Spring Data JPA/Hibernate`.
- Миграции: `Flyway` (набор `V1...V12`).
- Есть связи между сущностями (минимум 5 сущностей выполнено).
- Есть транзакционные сценарии (`@Transactional`) и защита от гонок для refresh-токенов (`PESSIMISTIC_WRITE` lock в репозитории).
- Есть OpenAPI через `springdoc-openapi` + конфиг.
- Есть интеграционные тесты с `Testcontainers` (PostgreSQL).
- Есть backend CI (`.github/workflows/ci.yaml`) с запуском тестов.
- Dockerfile backend есть.

Что не закрыто / частично:
- Нет Redis и `@Cacheable`-сценария.
- Нет `@Async`/`@Scheduled` практического сценария.
- Нет `Spring Actuator` (`/actuator/health`, `/actuator/metrics`).
- Unit-тесты как отдельный слой почти не выделены (в основном интеграционные).
- Нет общего корневого `docker-compose` для поднятия всей системы целиком (backend+frontend+инфраструктура).

## Frontend

**Оценка готовности frontend: 80%**

Что уже сделано:
- Стек соответствует: `Vue 3 + TypeScript`.
- Ключевые UI-сценарии из фич-листа в целом покрыты (логин, роли, списки, карточки, создание/редактирование).
- Ограничение действий по ролям есть и в роутинге/UI (guard'ы и role-checks).
- Архитектурно есть разделение по слоям: `views/pages`, `components`, `stores`, `api`.
- Нет прямых HTTP-вызовов в шаблонах компонентов (вызовы вынесены в `api`/`stores`).

Что не закрыто / частично:
- Нет `Dockerfile` для frontend.
- Нет frontend CI pipeline с `build + test + lint/static checks` в формате общего приемочного требования (есть deploy workflow, но не полноценный quality pipeline).

## Оценка по чеклисту приемки

### Выполнено
- Роли и доступы (минимум 2 роли с разными правами).
- Минимум 5 сущностей и связи между сущностями.
- Kotlin + Spring Boot (backend), Vue 3 + TypeScript (frontend).
- Слойность backend + DTO + валидация + централизованный обработчик ошибок.
- PostgreSQL + JPA/Hibernate.
- Flyway миграции.
- JWT + role-based security (реально используется).
- Интеграционные тесты backend через Testcontainers.
- OpenAPI/Swagger подключен.
- Frontend покрывает ключевые пользовательские сценарии.
- Архитектурная чистота frontend в целом соблюдена.

### Частично выполнено
- CI/CD: backend CI есть; frontend quality CI (build+test+lint) в едином формате отсутствует.
- Контейнеризация: backend Dockerfile и backend compose есть, но нет полного one-command подъема всего проекта из корня.

### Не выполнено
- Redis + `@Cacheable`.
- `@Async` и/или `@Scheduled` предметный сценарий.
- Spring Actuator health/metrics.
- Dockerfile frontend + общий `docker-compose up` из корня для backend+frontend+инфры.

## Что осталось добавить для 100% готовности

1. Добавить `Redis` + 1 read-heavy endpoint с `@Cacheable`
2. Добавить 1 фоновой сценарий через `@Scheduled` или `@Async` (пересчет статуса мониторинга/уведомления).
3. Подключить `Spring Actuator` и открыть `health/metrics`.
4. Сделать `frontend/Dockerfile` и корневой `docker-compose.yml` (backend + frontend + postgres + redis).
5. Добавить frontend quality workflow (`npm ci`, `npm run build`, lint).
6. Добавить хотя бы минимальные unit-тесты backend сервисов.
